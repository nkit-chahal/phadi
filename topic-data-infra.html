📖 Core Components

1. Data Lake vs Data Warehouse

  • Data Lake: Raw data, schema-on-read, cheap storage (S3, GCS)
  • Data Warehouse: Structured, optimized for queries (BigQuery, Snowflake)
  • Lakehouse: Combines both (Delta Lake, Iceberg)

2. Stream Processing

  • Kafka: Message queue, high throughput
  • Flink/Spark Streaming: Real-time processing
  • Use cases: Real-time features, event-driven ML

3. Feature Store

  • Offline store: Historical features for training (Hive, BigQuery)
  • Online store: Low-latency for serving (Redis, DynamoDB)
  • Point-in-time joins: Prevent feature leakage
  • Tools: Feast, Tecton, Vertex AI Feature Store

4. Data Quality

  • Schema validation: Expected types, columns
  • Statistical checks: Distributions, null rates
  • Tools: Great Expectations, dbt tests, Monte Carlo

Python Feast Feature Store 
from feast import FeatureStore, Entity, Feature, FeatureView
from feast import FileSource

# Define entity
user = Entity(
    name="user_id",
    description="User identifier"
)

# Define feature source
user_features_source = FileSource(
    path="data/user_features.parquet",
    timestamp_field="event_timestamp"
)

# Define feature view
user_features = FeatureView(
    name="user_features",
    entities=["user_id"],
    features=[
        Feature(name="age", dtype=Float32),
        Feature(name="total_purchases", dtype=Int64),
        Feature(name="avg_order_value", dtype=Float32),
    ],
    source=user_features_source,
    ttl=timedelta(days=1)
)

# Initialize store
store = FeatureStore(repo_path=".")

# Get historical features for training
training_df = store.get_historical_features(
    entity_df=entity_df,  # user_id + timestamp
    features=["user_features:age", "user_features:total_purchases"]
).to_df()

# Get online features for serving
online_features = store.get_online_features(
    features=["user_features:age", "user_features:total_purchases"],
    entity_rows=[{"user_id": 123}]
).to_dict()
Python Data Quality with Great Expectations 
import great_expectations as ge

# Load data
df = ge.read_csv("training_data.csv")

# Define expectations
df.expect_column_to_exist("user_id")
df.expect_column_values_to_not_be_null("user_id")
df.expect_column_values_to_be_between("age", min_value=0, max_value=120)
df.expect_column_values_to_be_in_set("gender", ["M", "F", "Other"])
df.expect_column_mean_to_be_between("purchase_amount", min_value=10, max_value=1000)

# Validate
results = df.validate()

if not results["success"]:
    print("Data quality check failed!")
    for result in results["results"]:
        if not result["success"]:
            print(f"  Failed: {result['expectation_config']['expectation_type']}")
else:
    print("All data quality checks passed!")

🎤 Interview Questions & Answers

Q1 What is a feature store and why use one? +

Answer:

A centralized repository for ML features with:

  • Consistency: Same features in training and serving
  • Reusability: Share features across teams
  • Point-in-time correctness: Prevents data leakage
  • Low latency serving: Online store for real-time
Q2 How do you handle data quality in ML? +

Answer:

  • Schema validation: Check types, required columns
  • Statistical tests: Distribution shifts, null rates
  • Automated alerts: Trigger on anomalies
  • Training gates: Block training if data fails checks
  • Tools: Great Expectations, dbt tests
