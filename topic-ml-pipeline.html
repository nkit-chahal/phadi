ML Pipeline Architecture

End-to-end pipelines from data to deployment (MLOps)

📌 Pipeline Overview

Data Sources → Ingestion → Validation → Transform → Feature Store
                                                         ↓
Monitoring ← Serving ← Registry ← Evaluation ← Training ←

📖 Pipeline Components

1. Data Ingestion

  • Batch: Daily/hourly ETL from data warehouse
  • Streaming: Kafka, Kinesis for real-time events
  • Tools: Airflow, Prefect, Dagster for orchestration

2. Data Validation

  • Schema validation: Expected columns, types
  • Statistical checks: Distribution drift, missing values
  • Tools: Great Expectations, TensorFlow Data Validation

3. Feature Engineering & Store

  • Feature Store: Central repo for features (Feast, Tecton)
  • Benefits: Reusability, consistency between training/serving
  • Offline store: Historical features for training
  • Online store: Low-latency features for serving

4. Training Pipeline

  • Experiment tracking: MLflow, Weights & Biases
  • Hyperparameter tuning: Optuna, Ray Tune
  • Distributed training: Ray, Horovod
  • Versioning: DVC for data, Git for code

5. Model Registry

  • Version control for models
  • Stage management: dev → staging → production
  • Tools: MLflow Model Registry, Vertex AI

6. Serving & Deployment

  • Containers: Docker + Kubernetes
  • Serving: TensorFlow Serving, TorchServe, Triton
  • Serverless: AWS Lambda, Cloud Functions

7. Monitoring

  • Model performance: Accuracy drift
  • Data drift: Input distribution changes
  • System: Latency, throughput, errors
  • Tools: Evidently, Arize, custom dashboards

🎤 Interview Questions & Answers

Q1 What is a feature store and why use one? +

Answer:

A feature store is a centralized repository for storing and serving ML features.

Benefits:

  • Consistency: Same features for training and serving
  • Reusability: Share features across teams/models
  • Freshness: Automated feature updates
  • Point-in-time correctness: Prevents data leakage

Examples: Feast (open source), Tecton, Vertex AI Feature Store

Q2 How do you handle model versioning? +

Answer:

  • Code: Git with tags for releases
  • Data: DVC (Data Version Control) or S3 versioning
  • Models: MLflow Model Registry with stages
  • Experiments: MLflow/W&B for tracking all runs

Each model version should link to: code commit, data version, training params, and metrics.
