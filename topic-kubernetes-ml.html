Kubernetes (K8s) Fundamentals

Orchestrating containerized ML applications at scale

📌 Why K8s?

Docker runs containers. Kubernetes manages ("orchestrates") them. It handles scaling, self-healing (restarting crashed containers), and networking.

1. Architecture Components

📦
Pod

The atomic unit. A wrapper around one or more containers. "A Pod is a single instance of your app".

🖥️
Node

The worker machine (VM or Bare metal) where Pods run.

🎮
Deployment

Controller that manages Pods. "I want 3 replicas of this Pod". It creates and monitors them.

🌐
Service

Stable Network Interface. Pods die and change IPs; Service provides a static IP to talk to them.

2. K8s Manifests (YAML)

YAML ml-deployment.yaml 
# 1. Deployment: Runs the App
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ml-model-v1
spec:
  replicas: 3  # Run 3 copies
  selector:
    matchLabels:
      app: fraud-detection
  template:
    metadata:
      labels:
        app: fraud-detection
    spec:
      containers:
      - name: model-container
        image: my-registry/fraud-model:1.0
        ports:
        - containerPort: 8000
        resources:
          limits:
            memory: "2Gi"
            cpu: "1"
---
# 2. Service: Exposes the App
apiVersion: v1
kind: Service
metadata:
  name: ml-service
spec:
  selector:
    app: fraud-detection
  ports:
  - protocol: TCP
    port: 80
    targetPort: 8000
  type: ClusterIP  # Internal only

3. Common Commands

Bash kubectl cheatsheet 
# Apply configuration
kubectl apply -f ml-deployment.yaml

# Check status
kubectl get pods
kubectl get services

# View logs (debugging)
kubectl logs ml-model-v1-xxxxx

# Enter container shell
kubectl exec -it ml-model-v1-xxxxx -- /bin/bash
