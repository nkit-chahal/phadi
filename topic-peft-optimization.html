📖 Deep Dive into Efficiency

1. DoRA (Weight-Decomposed LoRA)

LoRA updates both magnitude and direction simultaneously. DoRA decouples them, allowing the model to learn more like a full fine-tune while keeping the parameter efficiency of LoRA. It consistently outperforms LoRA on downstream tasks.

2. GaLore (Gradient Low-Rank Projection)

Unlike LoRA which adds adapters, GaLore projects the gradients into a low-rank space. This allows full-parameter fine-tuning of a 7B model on a consumer GPU (24GB VRAM) without adding any inference latency.

3. BitNet & ternary weights

BitNet binarizes (or ternarizes) the weights during training. This eliminates the need for expensive floating-point multiplications, replacing them with simple additions. This could lead to a 10x energy reduction in AI hardware.

🎤 Interview Q&A

Q1 What is the advantage of DoRA over LoRA? +

Answer:

LoRA limits the update to a specific low-rank subspace. DoRA decomposes the weight change into magnitude and direction. By allowing the model to update these independently, it mimics full fine-tuning behavior more closely, resulting in better learning stability and higher accuracy, especially on small datasets.

Q2 Explain the difference between GGUF and EXL2 formats. +

Answer:

  • GGUF (llama.cpp): Designed for "CPU + GPU" offloading. Very stable, works on almost any hardware (Mac Silicon, Windows, Linux).
  • EXL2 (ExLlamaV2): Native GPU quantization. Much faster than GGUF for single-GPU inference, supports variable bitrate (e.g., 4.65 bits per weight for optimal quality).

✍️ Practice Problem

Scenario: You have a 70B parameter model and only one 24GB GPU. You want to fine-tune it. Which technique would you choose and why?

You should use QLoRA (4-bit Quantized LoRA). Even GaLore requires too much memory for a 70B model on 24GB. QLoRA quantizes the base 70B model to 4-bit (reducing it from ~140GB to ~35GB VRAM), and then uses paged optimizers to handle the remaining memory spikes. For 70B, you would likely still need FSDP + QLoRA across multiple GPUs or a extremely high compression ratio.
