Search & Ranking

Design search systems with ML-powered ranking

📌 Search Pipeline

Query → Query Understanding → Retrieval → Ranking → Re-ranking → Results
              ↓                   ↓           ↓           ↓
         Spell check,        BM25 +      L2R model   Personalize,
         Expansion,         Semantic                 Diversity
         Intent

📖 Search Components

1. Query Understanding

  • Spell correction: Fix typos (Levenshtein, neural)
  • Query expansion: Add synonyms, related terms
  • Intent classification: Navigational, informational, transactional
  • Entity recognition: Extract products, brands, categories

2. Retrieval

  • Lexical (BM25): Fast, keyword matching
  • Semantic: Dense embeddings, captures meaning
  • Hybrid: Combine both (most effective)

3. Ranking (Learning to Rank)

  • Pointwise: Predict relevance score per document
  • Pairwise: Learn which doc is more relevant (RankNet)
  • Listwise: Optimize entire list (LambdaMART, LambdaRank)

4. Features for Ranking

  • Query-document: BM25, TF-IDF, embedding similarity
  • Document: PageRank, freshness, quality score
  • User: Past clicks, preferences, location
  • Context: Device, time, session

💻 Code Examples

Python Hybrid Search (BM25 + Semantic) 
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer
import numpy as np

class HybridSearcher:
    def __init__(self, documents):
        self.documents = documents
        
        # BM25 index
        tokenized = [doc.lower().split() for doc in documents]
        self.bm25 = BM25Okapi(tokenized)
        
        # Semantic embeddings
        self.encoder = SentenceTransformer('all-MiniLM-L6-v2')
        self.embeddings = self.encoder.encode(documents)
    
    def search(self, query, k=10, alpha=0.5):
        """
        Hybrid search combining BM25 and semantic.
        alpha: weight for BM25 (1-alpha for semantic)
        """
        # BM25 scores
        bm25_scores = self.bm25.get_scores(query.lower().split())
        bm25_scores = bm25_scores / (bm25_scores.max() + 1e-8)  # Normalize
        
        # Semantic scores
        query_emb = self.encoder.encode([query])[0]
        semantic_scores = np.dot(self.embeddings, query_emb)
        semantic_scores = (semantic_scores + 1) / 2  # Normalize to [0,1]
        
        # Combine
        combined = alpha * bm25_scores + (1 - alpha) * semantic_scores
        
        # Top-k
        top_indices = np.argsort(combined)[::-1][:k]
        return [(self.documents[i], combined[i]) for i in top_indices]

# Usage
searcher = HybridSearcher(documents)
results = searcher.search("machine learning tutorial", k=5)

🎤 Interview Questions & Answers

Q1 Design a search system for e-commerce. +

Answer Framework:

  1. Query understanding: Spell check, category detection, brand extraction
  2. Retrieval: Hybrid (BM25 + semantic), filtered by category/availability
  3. Ranking features:
    • Relevance: BM25, embedding similarity
    • Popularity: Sales, views, ratings
    • Personalization: User history, preferences
    • Business: Margin, inventory, promoted
  4. Metrics: CTR, Add-to-cart, Revenue per search
Q2 What is Learning to Rank? +

Answer:

ML approach to rank documents by relevance:

  • Pointwise: Regression on relevance score
  • Pairwise: Binary classification on pairs (which is more relevant)
  • Listwise: Directly optimize ranking metrics (NDCG)

LambdaMART (listwise) is most popular - uses gradient boosting with lambdas that approximate NDCG gradient.

Q3 How does this relate to your RAG work? +

Answer (Your Project):

RAG is essentially search + generation:

  • Retrieval: Same concepts - BM25 + semantic hybrid
  • Ranking: Reranking step with cross-encoder
  • Difference: Instead of showing results, feed to LLM

At Trident, I used hybrid search (semantic + machine code matching) - same principle as e-commerce search but for technical documents.
