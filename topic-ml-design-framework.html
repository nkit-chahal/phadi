ML System Design

ML System Design Framework

A structured approach to tackle any ML system design question

📌 The 6-Step Framework

┌─────────────────────────────────────────────────────────────────┐
│  1. PROBLEM     →  2. METRICS    →  3. DATA                     │
│  Clarify scope     Define success    Sources & pipelines        │
├─────────────────────────────────────────────────────────────────┤
│  4. MODEL       →  5. SERVING    →  6. MONITORING               │
│  Architecture      Deployment        Detect & fix issues        │
└─────────────────────────────────────────────────────────────────┘
⏱️
Time Management

45 min interview: 5 min clarify, 10 min data, 15 min model, 10 min serving, 5 min monitoring

📖 Step 1: Problem Definition (5 min)

Always Clarify:

  • Business goal: What are we trying to achieve? Revenue? Engagement?
  • User experience: How will this affect the user?
  • Constraints: Latency, throughput, cost, resources
  • Scale: How many users? Requests per second?

Example Questions to Ask:

  • "What's the acceptable latency? Real-time (<100ms) or batch is fine?"
  • "How much training data do we have?"
  • "Is this a new system or improving existing?"
  • "What's the cost budget for infrastructure?"

📊 Step 2: Define Metrics (5 min)

Offline Metrics (Development)

  • Classification: Precision, Recall, F1, AUC-ROC
  • Regression: MSE, MAE, R²
  • Ranking: NDCG, MRR, MAP
  • Recommendation: Hit Rate, Coverage, Diversity

Online Metrics (Production)

  • Business: CTR, Conversion, Revenue, DAU
  • User Experience: Session time, Bounce rate
  • System: Latency (p50, p99), Throughput, Error rate

Counter Metrics (Guardrails)

Metrics that should NOT degrade: e.g., if optimizing engagement, ensure content quality doesn't drop.

📦 Step 3: Data (10 min)

Data Sources

  • User interactions (clicks, views, purchases)
  • User profiles (demographics, preferences)
  • Item/content features
  • Contextual data (time, location, device)

Data Pipeline

Raw Data → ETL → Feature Store → Training Pipeline
                      ↓
              Real-time Features → Serving

Key Considerations

  • Labeling: How do we get labels? Explicit feedback vs implicit signals
  • Freshness: How often should data be updated?
  • Quality: Missing values, outliers, biases
  • Privacy: PII handling, GDPR compliance

🧠 Step 4: Model (15 min)

Start Simple, Then Iterate

  1. Baseline: Rule-based or simple heuristic
  2. Simple ML: Logistic regression, XGBoost
  3. Deep Learning: If needed and justified

Feature Engineering

  • User features: history, preferences, demographics
  • Item features: category, price, embeddings
  • Cross features: user-item interactions
  • Temporal features: time of day, recency

Model Architecture Choices

  • Recommendation: Two-tower, Wide & Deep, DCN
  • Ranking: GBDT, LambdaMART, Transformer
  • NLP: BERT, fine-tuned LLM
  • Vision: CNN, ViT

🚀 Step 5: Serving (10 min)

Serving Options

  • Batch: Pre-compute predictions, store in cache
  • Real-time: Compute on request, higher latency
  • Hybrid: Batch for candidates, real-time for ranking

Optimization Techniques

  • Model: Quantization, pruning, distillation
  • Infra: GPU serving, batching, caching
  • Architecture: Two-stage (retrieval + ranking)

A/B Testing

  • Random traffic split
  • Statistical significance (usually 95%)
  • Watch for novelty effects
  • Canary deployment for safety

📈 Step 6: Monitoring (5 min)

What to Monitor

  • Model performance: Accuracy/precision drift
  • Data drift: Input distribution changes
  • System health: Latency, errors, throughput
  • Business metrics: CTR, revenue impact

Handling Issues

  • Alerts: Set thresholds for key metrics
  • Fallback: Serve cached/baseline predictions
  • Retraining: Scheduled or triggered by drift

🎤 Interview Questions & Answers

Q1 How do you approach an ML system design question? +

Answer:

I follow a structured 6-step framework:

  1. Clarify: Understand problem, constraints, scale
  2. Metrics: Define offline and online success metrics
  3. Data: Identify sources, pipeline, features
  4. Model: Start simple, justify complexity
  5. Serving: Batch vs real-time, optimization
  6. Monitoring: Drift detection, alerts, retraining

I always start by asking clarifying questions to ensure I'm solving the right problem.

Q2 What's the difference between offline and online metrics? +

Answer:

  • Offline metrics (development): Measured on held-out test set. Examples: AUC, NDCG, MSE. Used to compare models before deployment.
  • Online metrics (production): Measured on live traffic. Examples: CTR, revenue, session time. The ultimate measure of success.

Offline metrics proxy online metrics but don't always correlate perfectly. A model with better AUC might not improve CTR. That's why A/B testing is essential.

Q3 When would you use batch vs real-time serving? +

Answer:

Batch serving:

  • Predictions don't need to be real-time
  • Large candidate set (pre-compute recommendations)
  • Cost-sensitive (cheaper to batch process)

Real-time serving:

  • Need fresh context (current session, location)
  • Personalization based on recent behavior
  • Dynamic content (search, fraud detection)

Hybrid: Batch for candidate generation, real-time for final ranking (most common for recommendations).

Q4 Walk through an ML system you designed. +

Answer (Your Project - RAG at Trident):

  • Problem: Reduce machine breakdown resolution time
  • Metrics: Resolution time (primary), operator satisfaction, retrieval relevance
  • Data: 50K breakdown reports, maintenance manuals, chunked for RAG
  • Model: Embeddings (ada-002) + GPT-4 for generation
  • Serving: Real-time API, <2s response time requirement
  • Monitoring: RAGAS metrics, operator feedback loop, usage analytics

Result: 30% reduction in resolution time.
