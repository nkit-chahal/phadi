🚀 Efficient LLM Inference

Modern techniques to run 7B+ parameter models on consumer hardware/production with low latency.

1. Quantization Techniques

📉
QLoRA (4-bit)

Dramatically reduces VRAM. Locks base model in 4-bit, trains adapters (LoRA) in FP16.

🔡
GPTQ / AWQ

Post-training quantization (PTQ) algorithms. Better specific for inference than bitsandbytes (QLoRA).

2. Throughput Optimization

  • vLLM & PagedAttention: Manages KV cache like OS virtual memory. 2-4x higher throughput than HuggingFace.
  • FlashAttention-2: Optimizes exact attention calculation on GPU IO. Sub-quadratic memory usage.
  • Speculative Decoding: Uses a small draft model to predict tokens, large model verifies them. Speedup without quality loss.

🏗️ Deployment Strategies

| Strategy       | Description                                      | Risk | Cost | Use Case              |
|----------------|--------------------------------------------------|------|------|-----------------------|
| **Canary**     | small % of traffic to new model. Roll out slowly.| Low  | Low  | Standard updates      |
| **Shadow**     | New model takes traffic but output ignored.      | Zero | High | Testing accuracy/load |
| **Blue/Green** | 2 identical envs. Switch router instantly.       | Med  | High | Instant rollback need |
| **A/B Test**   | Splitting users to compare business metrics.     | Med  | High | Checking conversion   |

🧪 The ML Testing Pyramid

  • 1. Infrastructure Tests: "Can we serve a request?" (Health checks, Latency SLAs)
  • 2. Model Integrity Tests: "Is the model structure correct?" (Input shapes, output ranges, not outputting NaN)
  • 3. Data Tests: "Is input garbage?" (Schema validation, Null checks, Feature drift)
  • 4. Performance Tests: "Is it smart enough?" (Accuracy/F1 on Golden Dataset, Bias checks)

🏪 Feature Stores (Feast/Tecton)

Solves "Training-Serving Skew" by syncing features between offline training and online serving.

Python Feast Example 
# 1. Define feature view (Batch source)
@feature_view(
    source=parquet_source, 
    schema=[Field(name="daily_transactions", dtype=Int64)],
    ttl=timedelta(days=1)
)
def user_stats_view(source):
    return source

# 2. Get historical features (for training)
training_df = store.get_historical_features(
    entity_df=entity_df,
    features=["user_stats_view:daily_transactions"]
).to_df()

# 3. Materialize to online store (Redis)
store.materialize(start_date=now - timedelta(days=1), end_date=now)

# 4. Get online features (for serving)
features = store.get_online_features(
    features=["user_stats_view:daily_transactions"],
    entity_rows=[{"user_id": 1001}]
).to_dict()

🎤 Interview Questions

Q1 How does vLLM improve inference?

PagedAttention: It treats KV Cache (Key-Value memory) like OS virtual memory. Instead of pre-allocating contiguous memory (wasteful), it allocates pages on demand. This reduces memory waste, allowing larger batch sizes = higher throughput.

Q2 What is Training-Serving Skew?

Difference in model performance during training vs production. Causes: Data leakage, Different feature pipelines (different code for SQL vs Python), Feedback loops. Fix: Use a Feature Store to unify logic.

Q3 Explain QLoRA vs standard Fine-tuning.

Standard fine-tuning updates all weights (expensive). LoRA freezes weights and updates low-rank adapters (cheaper). QLoRA goes further: it quantizes the frozen base model to 4-bit (Normal Float 4) to fit on smaller GPUs, while keeping adapters in 16-bit for stability.
