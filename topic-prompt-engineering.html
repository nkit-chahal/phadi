Prompt Engineering

Crafting effective prompts for optimal LLM outputs

📌 Key Principles

🎯
Be Specific

Clear instructions, explicit constraints, define output format

📝
Give Examples

Few-shot prompting for complex tasks, show expected format

🧠
Chain of Thought

"Think step by step" improves reasoning on complex problems

📖 Prompt Engineering Techniques

1. Zero-Shot Prompting

Direct instruction without examples. Works for simple tasks.

Classify the sentiment of this review as positive, negative, or neutral: [review]

2. Few-Shot Prompting

Provide examples to guide the output format and style.

Example 1: "Great product!" → positive Example 2: "Terrible quality" → negative Example 3: "It's okay" → neutral Classify: "Absolutely loved it!" → ?

3. Chain of Thought (CoT)

Ask the model to reason step by step. Hugely improves math/logic tasks.

"Let's think through this step by step..."

4. Role Prompting

Assign a persona to influence response style and expertise.

"You are an expert machine learning engineer at Google..."

5. Output Format Constraints

Specify exact output format for structured data.

Respond in JSON format: { "issue": "...", "root_cause": "...", "solution": "..." }

6. System vs User vs Assistant Messages

  • System: Sets overall behavior, rules, persona
  • User: The actual question/request
  • Assistant: Previous AI responses (for context)

Python Structured Prompt for RAG 
from openai import AzureOpenAI

def create_rag_prompt(query, context_docs):
    """Create a well-structured prompt for RAG."""
    
    system_prompt = """You are a technical support assistant for manufacturing equipment.
    
RULES:
- Only answer based on the provided context
- If the answer is not in the context, say "I don't have information about this"
- Be concise and actionable
- Include specific part numbers or procedures when available
- Cite the source document for each claim"""

    # Format context
    context = "\n\n".join([
        f"[Source: {doc.metadata['source']}]\n{doc.page_content}"
        for doc in context_docs
    ])
    
    user_prompt = f"""Context documents:
{context}

---
Question: {query}

Provide a helpful answer based only on the context above. Include citations."""

    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_prompt}
    ]

# Usage

response = client.chat.completions.create(
    model="gpt-4",
    messages=messages,
    temperature=0  # Low for factual accuracy
)
Python Few-Shot Prompting with Examples 
def classify_breakdown(description):
    """Classify breakdown type using few-shot prompting."""
    
    prompt = """Classify the machine breakdown into one of these categories:
- ELECTRICAL: motor, wiring, sensor, PLC issues
- MECHANICAL: bearing, gear, belt, alignment issues  
- PNEUMATIC: air pressure, valve, cylinder issues
- SOFTWARE: program, HMI, communication issues

Examples:
Description: "Motor making grinding noise and overheating"
Category: MECHANICAL (bearing failure causing motor strain)

Description: "PLC showing communication error with HMI"
Category: SOFTWARE (communication protocol issue)

Description: "Cylinder not extending fully, air leaking"
Category: PNEUMATIC (valve or seal failure)

Now classify:
Description: "{description}"
Category:"""

    response = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt.format(description=description)}],
        temperature=0
    )
    
    return response.choices[0].message.content
Python Chain of Thought for Complex Reasoning 
def diagnose_with_cot(symptoms):
    """Use Chain of Thought for multi-step diagnosis."""
    
    prompt = f"""You are diagnosing a machine issue. Think through this step by step.

Symptoms reported: {symptoms}

Please analyze as follows:
1. List all possible root causes for these symptoms
2. For each cause, explain what evidence would confirm or rule it out
3. Based on likelihood, rank the causes
4. Recommend the first diagnostic step

Think step by step:"""

    response = client.chat.completions.create(
        model="gpt-4",
        messages=[
            {"role": "system", "content": "You are an expert maintenance engineer."},
            {"role": "user", "content": prompt}
        ],
        temperature=0.3  # Slightly higher for reasoning variety
    )
    
    return response.choices[0].message.content

# Usage
result = diagnose_with_cot(
    "Conveyor belt slipping, motor temperature high, unusual vibration"
)

🎤 Interview Questions & Answers

Q1 What is few-shot prompting and when to use it? +

Answer:

Few-shot prompting provides examples of input-output pairs before the actual task.

When to use:

  • Complex output format that's hard to describe
  • Specific style or tone requirements
  • Classification with nuanced categories
  • Tasks where zero-shot gives inconsistent results

Best practices:

  • 3-5 examples usually sufficient
  • Include edge cases in examples
  • Keep examples representative and diverse
Q2 How does Chain of Thought improve LLM reasoning? +

Answer:

CoT prompting asks the model to show its reasoning process before giving a final answer.

Why it works:

  • Forces the model to break down complex problems
  • Each reasoning step becomes context for the next
  • Reduces errors in multi-step reasoning
  • Makes debugging easier - you can see where reasoning went wrong

When to use: Math problems, logic puzzles, multi-step analysis, debugging.

Q3 What's the difference between temperature and top_p? +

Answer:

  • Temperature (0-2): Controls randomness. Lower = more deterministic, higher = more creative.
  • Top_p (0-1): Nucleus sampling. Considers only tokens whose cumulative probability exceeds p.

Guidelines:

  • Factual tasks (RAG, classification): temp=0
  • Creative writing: temp=0.7-1.0
  • Code generation: temp=0-0.2
  • Generally, tune one or the other, not both
Q4 How did you design prompts in your RAG system? +

Answer (Your Project):

For the breakdown intelligence system at Trident:

  • System prompt: Defined role as "maintenance expert", set rules to only use retrieved context
  • Context formatting: Each chunk with source metadata for citations
  • Output structure: JSON with issue, root_cause, solution, confidence fields
  • Grounding: "If answer not in context, say 'no information available'"
  • Temperature: 0 for consistent, factual responses
