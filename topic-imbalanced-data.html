Imbalanced Data

Techniques for handling skewed class distributions

📌 Quick Summary

📈
Oversampling (SMOTE)

Create synthetic minority samples. Risk: overfitting to synthetic data.

📉
Undersampling

Remove majority samples. Risk: lose information.

⚖️
Class Weights

Penalize majority class errors more. Clean, no data manipulation.

📖 Techniques Overview

1. Oversampling

  • Random Oversampling: Duplicate minority samples (can overfit)
  • SMOTE: Create synthetic samples by interpolating between nearest neighbors
  • ADASYN: Focus on hard-to-learn samples

2. Undersampling

  • Random Undersampling: Remove majority samples (loses information)
  • Tomek Links: Remove majority samples close to decision boundary
  • NearMiss: Keep majority samples closest to minority

3. Class Weights

  • Assign higher loss penalty to minority class
  • weight = n_samples / (n_classes × n_samples_per_class)
  • Clean solution, no data manipulation

4. Specialized Loss Functions

  • Focal Loss: Down-weights easy examples, focuses on hard ones
  • γ=2 is typical, higher γ = more focus on hard examples

5. Threshold Adjustment

  • Default threshold is 0.5 for binary classification
  • Lower threshold increases recall (catch more positives)
  • Use precision-recall curve to find optimal threshold

6. Ensemble Methods

  • BalancedBagging: Train each estimator on balanced subset
  • EasyEnsemble: Create ensemble from undersampled datasets

💻 Code Examples

Python SMOTE Oversampling 
from imblearn.over_sampling import SMOTE, ADASYN
from collections import Counter

print(f"Before: {Counter(y_train)}")
# Output: Counter({0: 9000, 1: 100})

# SMOTE - create synthetic minority samples
smote = SMOTE(random_state=42)
X_resampled, y_resampled = smote.fit_resample(X_train, y_train)

print(f"After SMOTE: {Counter(y_resampled)}")
# Output: Counter({0: 9000, 1: 9000})

# ADASYN - focus on hard samples
adasyn = ADASYN(random_state=42)
X_resampled, y_resampled = adasyn.fit_resample(X_train, y_train)

# Important: Only apply to training data, NOT validation/test!
Python Class Weights in Scikit-learn 
from sklearn.utils.class_weight import compute_class_weight
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression

# Automatic class weight computation
class_weights = compute_class_weight(
    class_weight='balanced',
    classes=np.unique(y_train),
    y=y_train
)
weight_dict = dict(zip(np.unique(y_train), class_weights))
print(f"Class weights: {weight_dict}")
# Output: {0: 0.52, 1: 4.95}  # Minority class weighted higher

# Use in models
rf = RandomForestClassifier(class_weight='balanced')
lr = LogisticRegression(class_weight='balanced')

# Manual weights
custom_weights = {0: 1, 1: 10}  # 10x penalty for missing minority
rf = RandomForestClassifier(class_weight=custom_weights)
Python Class Weights in PyTorch 
import torch
import torch.nn as nn

# Calculate weights from class frequencies
class_counts = [9000, 100]  # majority, minority
total = sum(class_counts)
weights = torch.tensor([total/c for c in class_counts])
weights = weights / weights.sum()  # Normalize

print(f"Weights: {weights}")
# Output: tensor([0.011, 0.989])

# Use in CrossEntropyLoss
criterion = nn.CrossEntropyLoss(weight=weights)

# For binary with BCEWithLogitsLoss
pos_weight = torch.tensor([class_counts[0] / class_counts[1]])  # 90
criterion = nn.BCEWithLogitsLoss(pos_weight=pos_weight)
Python Threshold Optimization 
from sklearn.metrics import precision_recall_curve, f1_score

# Get probability predictions
y_proba = model.predict_proba(X_val)[:, 1]

# Find optimal threshold for F1
precisions, recalls, thresholds = precision_recall_curve(y_val, y_proba)
f1_scores = 2 * (precisions * recalls) / (precisions + recalls + 1e-8)
optimal_idx = np.argmax(f1_scores)
optimal_threshold = thresholds[optimal_idx]

print(f"Optimal threshold: {optimal_threshold:.3f}")
print(f"F1 at optimal: {f1_scores[optimal_idx]:.3f}")

# Use custom threshold for predictions
y_pred_custom = (y_proba >= optimal_threshold).astype(int)

🎤 Interview Questions & Answers

Q1 What is SMOTE and how does it work? +

Answer:

SMOTE (Synthetic Minority Over-sampling Technique) creates synthetic samples for the minority class:

  1. For each minority sample, find k nearest neighbors (typically k=5)
  2. Randomly select one neighbor
  3. Create new sample along the line between original and neighbor
  4. new_sample = original + rand(0,1) × (neighbor - original)

Pros: Creates realistic samples, reduces overfitting vs random duplication

Cons: Can create noisy samples if minority is scattered, doesn't work well in high dimensions

Q2 When would you use class weights vs SMOTE? +

Answer:

Use Class Weights when:

  • You want a clean, simple solution without data manipulation
  • Working with neural networks (easier integration)
  • Moderate imbalance (5:1 to 20:1)

Use SMOTE when:

  • Extreme imbalance (100:1+)
  • You have enough minority samples for meaningful interpolation
  • Tree-based models (work well with synthetic data)

Often best to combine both!

Q3 Should you apply SMOTE before or after train/test split? +

Answer: ALWAYS AFTER the split!

Only apply SMOTE to training data, never to validation or test.

Why? If applied before split, synthetic samples might end up in test set, causing data leakage. Your test set should represent real-world distribution.

# Correct order:
1. Split into train/val/test
2. Apply SMOTE only to X_train, y_train
3. Validate and test on original (imbalanced) data
Q4 How did you handle imbalanced data in your projects? +

Answer (Example Answer):

In my YOLOv5 defect detection at Lincode:

  • Problem: Some defect types had only 50 samples vs 2000+ for common types
  • Solutions used:
    • Class weights in loss function (per-class scaling)
    • Heavy data augmentation (rotation, flip, color jitter)
    • Focal loss to focus on hard examples
    • Ensemble with different augmentation seeds
  • Result: Rare defect recall improved from 65% to 88%
