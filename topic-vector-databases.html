Vector Databases

Storage and retrieval of embeddings for semantic search

📌 Quick Comparison

| Database   | Type      | Best For                    | Scale     |
|------------|-----------|-----------------------------| ----------|
| ChromaDB   | Embedded  | Prototyping, small-medium   | <1M       |
| FAISS      | Library   | Research, custom pipelines  | Millions  |
| Pinecone   | Managed   | Production, enterprise      | Billions  |
| Weaviate   | Self-host | Hybrid search, GraphQL      | Millions  |
| Qdrant     | Self-host | High performance, filtering | Millions  |

📖 Vector Database Options

ChromaDB

  • Type: Embedded / Client-server
  • Pros: Easy setup, great for development, Python-native
  • Cons: Not for massive scale (>1M vectors)
  • Best for: POCs, small-medium production, local development

FAISS (Facebook AI Similarity Search)

  • Type: Library (not a database)
  • Pros: Very fast, GPU support, battle-tested
  • Cons: No persistence by default, need to manage storage
  • Best for: Research, custom implementations, performance-critical

Pinecone

  • Type: Fully managed cloud service
  • Pros: Scalable, no ops, fast, metadata filtering
  • Cons: Paid, vendor lock-in
  • Best for: Production enterprise, teams without ML infra

Weaviate

  • Type: Self-hosted / Cloud
  • Pros: Hybrid search built-in, GraphQL API, modules
  • Cons: More complex setup
  • Best for: When you need hybrid search out-of-box

Qdrant

  • Type: Self-hosted / Cloud
  • Pros: Fast, good filtering, Rust-based, modern API
  • Cons: Newer ecosystem
  • Best for: High-performance self-hosted deployment

💻 Code Examples

Python ChromaDB Usage 
import chromadb
from chromadb.config import Settings

# Initialize client
client = chromadb.Client(Settings(
    chroma_db_impl="duckdb+parquet",
    persist_directory="./chroma_db"
))

# Create collection
collection = client.create_collection(
    name="breakdown_docs",
    metadata={"hnsw:space": "cosine"}  # Distance metric
)

# Add documents
collection.add(
    documents=["Motor overheating due to bearing failure", 
               "Sensor calibration procedure for pressure gauge"],
    metadatas=[{"machine": "CNC-01", "type": "electrical"},
               {"machine": "Press-02", "type": "calibration"}],
    ids=["doc1", "doc2"]
)

# Query
results = collection.query(
    query_texts=["how to fix overheating motor"],
    n_results=3,
    where={"machine": "CNC-01"}  # Metadata filtering
)

print(results["documents"])
print(results["distances"])
Python FAISS Usage 
import faiss
import numpy as np

# Create embeddings (example: 1536 dimensions like OpenAI)
dimension = 1536
num_vectors = 10000

# Random embeddings for demo
embeddings = np.random.random((num_vectors, dimension)).astype('float32')

# Build index
index = faiss.IndexFlatL2(dimension)  # L2 distance
print(f"Trained: {index.is_trained}")

# Add vectors
index.add(embeddings)
print(f"Total vectors: {index.ntotal}")

# Search
query = np.random.random((1, dimension)).astype('float32')
k = 5  # Top 5 results

distances, indices = index.search(query, k)
print(f"Nearest indices: {indices}")
print(f"Distances: {distances}")

# For large scale, use IVF index
nlist = 100  # Number of clusters
quantizer = faiss.IndexFlatL2(dimension)
index_ivf = faiss.IndexIVFFlat(quantizer, dimension, nlist)
index_ivf.train(embeddings)  # Must train on data
index_ivf.add(embeddings)
Python Pinecone Usage 
import pinecone
from pinecone import Pinecone, ServerlessSpec

# Initialize
pc = Pinecone(api_key="your-api-key")

# Create index
pc.create_index(
    name="breakdown-index",
    dimension=1536,
    metric="cosine",
    spec=ServerlessSpec(cloud="aws", region="us-east-1")
)

# Get index
index = pc.Index("breakdown-index")

# Upsert vectors
index.upsert(vectors=[
    {
        "id": "doc1",
        "values": [0.1, 0.2, ...],  # 1536 floats
        "metadata": {"machine": "CNC-01", "type": "electrical"}
    },
    {
        "id": "doc2", 
        "values": [0.3, 0.4, ...],
        "metadata": {"machine": "Press-02", "type": "calibration"}
    }
])

# Query with filtering
results = index.query(
    vector=[0.1, 0.2, ...],
    top_k=5,
    filter={"machine": {"$eq": "CNC-01"}},
    include_metadata=True
)

🎤 Interview Questions & Answers

Q1 How do vector databases work? +

Answer:

  1. Store: Vectors (embeddings) along with metadata and IDs
  2. Index: Build specialized index structure for fast search
  3. Query: Find vectors closest to query vector using distance metric

Key concept: ANN (Approximate Nearest Neighbor)

  • Exact search is O(n) - too slow for millions of vectors
  • ANN trades accuracy for speed - typically 95-99% recall at 10-100x speedup
  • Common algorithms: HNSW, IVF, LSH
Q2 What distance metrics are used and when? +

Answer:

  • Cosine similarity: Measures angle between vectors. Best for normalized embeddings, NLP tasks. Most common choice.
  • Euclidean (L2): Measures straight-line distance. Good when magnitude matters.
  • Dot product: Fast, assumes normalized vectors. Used by OpenAI embeddings.

For OpenAI embeddings (normalized), Cosine and Dot Product give same ranking.

Q3 Why did you choose ChromaDB over Pinecone? +

Answer (Your Project):

For the breakdown intelligence system at Trident:

  • Scale: ~50K documents - ChromaDB handles this easily
  • Cost: On-prem deployment, no SaaS fees
  • Simplicity: Easy integration with LangChain
  • Latency: Local = fast, no network roundtrip
  • Data sensitivity: Manufacturing data stays on-prem

Would choose Pinecone for: massive scale (>10M), multi-region, zero-ops requirement.

Q4 How do you handle updates in a vector database? +

Answer:

  • Upsert: Most DBs support upsert (insert or update by ID)
  • Re-embed: If document content changes, re-generate embedding
  • Versioning: Keep document version in metadata
  • Batch updates: For large updates, batch process to avoid index fragmentation

Best practice: Use document hash as ID - same content = same ID, automatic deduplication.
