📌 Why Docker for ML?

🔄
Reproducibility

Eliminate "It works on my machine". Same OS libs, same python versions everywhere.

📦
Portability

Build once, run anywhere (AWS, Azure, Local, On-prem).

🚀
Scalability

Evaluate instances easily with Kubernetes (K8s).

🛠️ Dockerfile Best Practices

Dockerfile Optimized Python ML Image 
# 1. Use slim base image (smaller attack surface, faster download)
FROM python:3.9-slim-buster

# 2. Set working dir
WORKDIR /app

# 3. Prevent python buffering (logs appear immediately)
ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

# 4. Install system dependencies (only if needed, e.g. for cv2)
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc \
    libgl1-mesa-glx \
    && rm -rf /var/lib/apt/lists/*

# 5. Copy requirements FIRST (for layer caching)
COPY requirements.txt .

# 6. Install python dependencies (no cache dir to save space)
RUN pip install --no-cache-dir -r requirements.txt

# 7. Copy remaining code
COPY . .

# 8. Create non-root user (Security Best Practice)
RUN useradd -m appuser
USER appuser

# 9. Expose port (metadata only)
EXPOSE 8000

# 10. Run command
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

Optimization Tips

  • Multi-stage builds: Build in one container, copy only artifacts to a second tiny container (good for compiled languages or heavy builds).
  • .dockerignore: EXCLUDE `.git`, `__pycache__`, `data/` (large datasets), `venv/`. Vital for small context!
  • Order Matters: Changing a line invalidates cache for ALL lines after it. Put things that change least (requirements) at top, code at bottom.

♾️ CI/CD for ML

Continuous Integration (CI) and Continuous Deployment (CD) adapted for Machine Learning (CT/CM: Continuous Training/Monitoring).

    Code Push      CI Pipeline       CD Pipeline        Production
    (Git)    ──▶  (Tests/Lint)  ──▶ (Deploy App)  ──▶  (Endpoint)
                        │                 │                │
                        ▼                 ▼                ▼
                   Unit Tests        Build Image      Monitor
                   Data Val          Push Registry    (Drift?) ──▶ Trigger Retrain ⟳

Key Differences for ML

  • Code + Data + Model: Version control isn't just git. You need DVC (Data Version Control) or MLflow.
  • Testing:
    • Unit Tests: Check code logic.
    • Data Tests: Check schema, nulls, ranges (Great Expectations).
    • Model Tests: Check accuracy not dropping below baseline.

🎤 Interview Questions

Q1 Difference between Docker and Virtual Machine?

VM has its own full OS (kernel). Heavy, slow boot. Docker containers share the host OS kernel. Lightweight, fast boot.

Q2 How to reduce Docker image size?

1) Use `slim` or `alpine` base images. 2) proper ordering of layers. 3) `.dockerignore` files. 4) Multi-stage builds. 5) `pip install --no-cache-dir`.
