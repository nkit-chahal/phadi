Feature Stores

Solving Training-Serving Skew and Feature consistency

📌 The Problem: Training-Serving Skew

Scenario: You train your model using SQL on a Data Warehouse (Batch). You serve your model using Python code helping an API (Online).

  • Training: Calculates "Average Order Value" over last 30 days using heavy SQL Query.
  • Serving: Calculates "Average Order Value" using a Redis lookup or python loop.
  • Result: Logic mismatch = Model performs great in Jupyter, fails in Prod.

The Solution: Feature Store

A centralized repository that manages feature logic and syncs values between "Offline" (Training) and "Online" (Serving) stores.

Core Components

💾
Offline Store

Cheap, high capacity (S3, BigQuery, Snowflake). Used for generating historical training datasets.

⚡
Online Store

Low latency, key-value (Redis, DynamoDB). Used for real-time inference lookup.

🔄
Registry

Definitions of feature logic. Ensures same code generates data for both stores.
